## The question

Salience is the strongest feature group for first-time breakouts (dropping it cut hard-row AUC 0.889 -> 0.833), but
for state elections only `jump` reaches the model. The raw weekly state Trends series have been cached since August
(`external/reference/trends/v6_AU_<STATE>_*`). Do the level, rise, peak, last-8-week share and within-election
percentiles rebuilt from those series, added as xgb features, predict seats better?

## What the branch does (read from the diff)

- `R/salience_state.R` (new): loads the cached series, rebuilds the two-stage anchor scaling (97.2% of 2,666
  keywords reproduce `salience-v6.csv`'s `jump` exactly), drops any point on or after polling day, computes six
  per-class features `ss_level, ss_rise, ss_peak, ss_share8, ss_jump_pctile, ss_level_pctile` (percentiles ranked
  among non-zero values only, NA below 10 positive values), `NA` (never a filler) where a candidacy has no series.
- `scripts/build_state_salience.R` (new): writes `output/state-salience-v1.csv`, `state-salience-features.csv` and a
  coverage table; stops if a feature column lands 100% NA; anchor check against `salience-v6.csv`.
- Switch wired into `scripts/fit_xgb_primary_v6.R` (features added; `feat_cols` extended only when on), the live
  predict path `xgb_primary_predict_live()`, `scripts/promote_rebuild.R` and `scripts/rebuild_forecasts.sh` (stage 3
  builds the table only when on). Switch 0 returns the feature table untouched (tested).
- `scripts/published_flags.R`: `AUSPOL_SALIENCE_STATE = "0"`. Tests: `tests/testthat/test-salience_state.R`
  (time-forward mutation-checked). `docs/DATA-REGISTRY.md` known-gaps line corrected.
- Coverage (build review): 3,503 of 4,663 NSW/VIC/SA/QLD candidacies (75%); **WA 0%** (cached queries are surname
  only, unmatched); federal and NT rows have none (federal salience is the separate v6 table); **Victoria 2026 has
  no series**.
- An xgb FEATURE, not a `base_pred` fix: it changes what the trees learn, so it reaches the backtests only through a
  retrain of the as-at models and the live forecast only through the production model.

## Screen and criterion

Instrument: `scripts/quick_arm.R`, AEF-7 default pairs (681 seats), `--sims=1000`, common random numbers.

- **Primary**: Q3, pooled seat-winner log loss on AEF-7, SE clustered on election, better by more than 1 SE.
- **Targeted** (cells with series, chosen from the feature table, never outcomes): seat log loss on the seats of the
  four AEF-7 elections that carry state series (nsw2023, qld2024, sa2026, vic2022) holding any cell whose published
  share moved by more than 0.05 points; Q2 squared share error on changed cells. Named breakouts read individually
  where they fall in AEF-7 (build review: jump percentile Yildiz 0.97, Regan 0.95 flagged; Butler, Birchall,
  Habermann silent at 0); which of these sit in AEF-7 elections is read from the feature table, not assumed.
- **Negative controls**: fed2022, fed2025 and wa2025 carry NO state series (all `ss_*` NA). Any change there comes
  from the retrain moving the trees, not from the feature.
- **Guards**: G1 Q3 not worse by more than 1 SE; G2 no AEF-7 election worse by more than 1 SE of its own paired
  seat differences (stricter than standard clause 4, set by tonight's brief; a G2-only refusal of an otherwise
  passing arm goes to Pete); G3 leave-one-election-out for a passing arm; G4 without the two largest-gain seats the
  targeted gain keeps its sign.

**Decision rule.** Passes the screen if the primary is better by more than 1 SE, or the primary is within 1 SE and
the targeted seat log loss is better by more than 1 SE (a feature acting on a quarter of the corpus needs about four
times the effect to show pooled), with G1 to G4 holding and nothing below unacceptable. Worse by more than 1 SE:
STOPPED. Otherwise "not shown", stays off, numbers to Pete. A pass earns the full test: both retrains taken through
stages 5 to 7 at 20,000 simulations over every election, scored by the standard rule, as the contest features were.

### What would make an apparent win unacceptable (named now)

- **The NA pattern acting as a jurisdiction label.** The `ss_*` columns are structurally NA on every federal, WA
  and NT row and on live vic2026, and populated on most NSW/VIC/SA/QLD rows, so a tree can split on missingness and
  learn "state election with series" versus "not" (the `state_elec_gap = 999` incident, 2026-09-12: 96% of
  non-federal predictions moved). Refused if the negative controls (fed2022, fed2025, wa2025) move by more than the
  OFF-vs-main retrain drift does, measured as mean |share change| on their cells, or if any of them is worse by more
  than 1 SE of its own seats.
- **Live vic2026 is all NA.** A model trained with vic2022 populated and served vic2026 empty treats Victoria 2026
  like a federal or WA row. Before shipping, walk the live forecast with and without (memory
  `walk-the-live-forecast`); any seat's favourite changing goes to Pete. The build review's own conclusion was that
  nothing learned here can act on vic2026 except through this path; a gain that exists only in the backtests and
  moves vic2026 only through missingness is not a reason to ship.
- A gain carried by seats where `ss_*` is NA (the gain must sit on cells with a series).
- A state class's statewide total in any AEF-7 election moving by more than 1 point (the features should move where
  a vote lands, not how much there is); reported to Pete.

### What the criterion cannot see

- Whether fetching vic2026 series (a data-acquisition task for Pete to approve, rate-limited) would make the
  features useful live. This screen measures backtest value only.
- WA, whose series are unmatched; a WA-matched version is a different build.
- Seats under the 0.5/N floor at 1,000 simulations.

## Dry run on known cases (prose, before any screen)

- **Switch off through the whole chain** (the OFF retrain against itself): Q3 exactly 0, every election
  byte-identical. The branch's test (switch 0 returns the table untouched) covers the function; this covers the chain.
- **The trap above, deliberately**: an AEF-7 `quick_arm.R` run of `AUSPOL_SALIENCE_STATE=1` WITHOUT the
  `AUSPOL_XGB_PRIMARY_OOF` pairing must come back byte-identical on all seven elections. If it does not, something
  other than the cached file is reading the switch and the wiring is not what the diff shows. Cheap (cached baseline);
  run it first.
- **Yildiz (jump percentile 0.97) and Regan (0.95)**, the two breakouts the build review flagged (which election
  each belongs to was not re-checked for this plan; read it from `state-salience-v1.csv`): their `ss_jump_pctile`
  in the ON copy's features file must be at or above 0.9. If either is NA, the candidacy match is broken and the
  screen waits.
- **A WA row in the ON features file**: every `ss_*` NA. A non-NA value means the surname-only queries were matched
  after all, and the coverage claim is wrong.

## Leakage

Series points on or after polling day are dropped (SSB3 must print 0). Percentiles are within one election over
pre-polling-day interest, no outcome. The as-at retrain trains each election's model only on earlier elections, as
the shipped as-at models do.

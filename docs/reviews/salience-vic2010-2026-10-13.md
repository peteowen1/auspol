# Salience for vic2010 (fetched 2026-10-13)

Pete decided (checklist item 2.9 / 7.2 in `add-pair-vic2010-checklist-2026-10-13.md`) to fetch Google Trends salience for the
vic2010 pair before scoring it, so it is scored like vic2014.

## 1. The chain vic2014 uses (verified in code)

| Step | What | Where |
|---|---|---|

| Builder | `scripts/fetch_salience_v6.R` (the `ELS` list; vic2014 entry: poll 2014-11-29, geo `AU-VIC`, anchor Denis Napthine). Candidates from `output/candidacies.csv`, search term via `search_form(given, surname, name)` |

## 2. What was built and fetched

- New script `scripts/fetch_salience_v6_vic2010.R`: a copy of `fetch_salience_v6.R` with a `vic2010` entry
  (poll 2010-11-27, `AU-VIC`, prev `vic2006`, anchor John Brumby, Premier at the time), default election `vic2010`,
  output `output/salience-v6-vic2010.csv` (does not touch `salience-v6.csv`), and a clean stop if Google throttles four times
  in a row. Window actually used: 2009-10-22 to 2010-11-26.
- One forced difference: vic2006 is not in `candidacies.csv`, so the "previous vote" used to pick the top 2 per seat was
  built in memory from `external/elections/vec-2006-vic-firstprefs.csv` (415 seat-party rows, 88 seats). 222 of 266 candidates
  have a nonzero previous vote. Seat names match (88 seats).
- Candidates: 266 non-major candidates in all 88 districts (IND 75, OTH_RIGHT 105, GRN 79, OTH 7), 54 batches of 5 plus the linking pass.
- **All 88 districts done. No throttling signal fired; 0 batches dropped.** Remaining: none.
- Raw cache: 57 new `.rds` files in `external/reference/trends/` whose names contain `2009_10_22_2010_11_26`
  (cache was 4,723 files before, 4,780 after). Rerunning the script reads them all from cache.
- Output: `output/salience-v6-vic2010.csv`, 266 rows, same 8 columns as `salience-v6.csv` (checked identical).
- The `elected` column is FALSE for every row: candidacies has no 2010 winners loaded (checklist 3.6), same cause as the NA the vic2014 path avoids by having winners.
  `elected` is therefore uninformative for vic2010. Check before merging whether any consumer uses it for vic (it drives the surge-v2 training, so vic2010
  would contribute zero emerged candidates there even if a winner such as an independent existed; 2010 had none in the non-major pool of the top-12 below).

## 3. Checks

Distribution of `jump` (higher = more search interest in the campaign than before it; most candidates are zero):

| Election | rows | % exactly zero | distinct values | max | rows > 0 |
|---|---|---|---|---|---|
| vic2014 | 365 | 91 | 59 | 17.06 | 32 |
| vic2018 | 255 | 86 | 32 | 0.09 | 36 |
| vic2010 (new) | 266 | 96 | 24 | 0.33 | 11 |

- vic2010 is much quieter than vic2014 and about as quiet as vic2018 (max 0.33). Only 11 candidates register at all, 24 distinct values.
  That is a genuine property of 2010-era search volume, not a dropped batch (0 dropped). Expect the surge hazard to be nearly flat for vic2010.
- Top jumps: Kathleen Oconnor (South Barwon, OTH_RIGHT, 1.8%) 0.334; Ross Douglass (Mildura, 1.5%) 0.309; Bruce Lindsay (Geelong, GRN, 11.5%) 0.268;
  Bruce Rogers (Bass, 3.5%) 0.268. These are not sensible "emergence" signals (low vote shares, probably namesakes or noise on thin volume).
  Salience here does not rank by first preference: a spot check of the loudest rows shows only the Greens at Geelong (11.5%) and Narre Warren North (6.9%)
  with any real vote. That is a weak-signal result, not evidence the fetch is broken; no cross-check of a known winner is possible because the pool excludes majors.
- Query form: surname-first bug avoided (terms are "Given Surname", e.g. "Kathleen Oconnor", apostrophes stripped as for vic2014); one initial-only term ("A Thompson", Brighton) returns 0.
- Not checked: whether Google's published figures for these 2010 queries are stable across refetches (not retried).

## 4. How to merge

1. Append the rows: `rbind(fread("output/salience-v6.csv"), fread("output/salience-v6-vic2010.csv"))` and write back (the script's own merge logic
   keeps other elections and replaces rows of the same `election`, so running `fetch_salience_v6.R` itself after adding the same `ELS` entry would also work and is a pure cache read).
2. Before the merge, check Victorian rows for duplicates of `(election, keyword, seat)`.
3. The harness also needs the vic2010 pair itself (checklist 1.3); `salience_permit_for()` and the surge hazard should then find vic2010 rows. Expect the
   `BV0b`/`BV0d` salience lines to report few cells set. Confirm in the first vic2010 log that the `tryCatch` "BV1... failed" lines do not appear.
4. If merged into `fetch_salience_v6.R` proper, add the `vic2010` entry (and `fetch_salience_v6_remaining.sh` list) and regenerate `docs/DATA-REGISTRY.md` and the data dictionary.
5. Nothing under `R/`, existing `scripts/`, `tests/` or existing `output/` was edited.

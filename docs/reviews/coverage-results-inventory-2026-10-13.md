This table lists, for every federal and mainland-state election from 2000 to 2026 (44 elections), which results data is already on disk, what is missing before the candidate-model harness can score it, where the missing piece can be downloaded (checked live on 2026-10-13), and the effort. Smaller effort is better.

Read-only inventory (track A of `docs/plans/coverage-program-2026-10-13.md`). Nothing under `R/`, `scripts/`, `tests/` or `.github/` was edited. Scratch downloads (ECQ 2009/2015 zips, AEC 2001 statistics zip) went to the session scratchpad, not the repo.

## How to read the table

- "Pair" means election plus its previous election. A harness scores an election using the previous election's first preferences and transfers, so each row needs both.
- **SCORED** rows are among the 23 pairs in `all_election_pairs()` today. Nothing is missing for them.
- Source status: **[live]** = I fetched it today and looked at the content; **[head]** = URL answered 200 but I did not read the body; **[unchecked]** = not reachable or not tried.
- "AE csv" means `external/aus-polling-analyser/analysis/Archived/elections/results_<year><jur>.csv`, already on disk (see finding 1). It is Antony Green-style compiled data from a third party, so it is a stopgap to cross-check against the commission source, not a replacement.
- Redistribution notes marked (memory) come from my recollection of when boundaries changed. I did not verify them. Check against `STATE_REDISTRIBUTIONS` in `R/state_notional.R` and the commission's redistribution page before building notionals.

## Key findings

1. **The anchor clone already holds candidate-level first preferences and two-candidate-preferred results for every election in scope except the ones marked.** `analysis/Archived/elections/results_*.csv` has, per seat, `fp` rows (candidate, party, votes, percent, swing) and `tcp` rows. Seat counts checked: fed 2001/2004/2007 = 150 each (fed 2010 = only 124, incomplete, and not needed because the AEC files are on disk); NSW 2003/2007/2011/2015 = 93; Vic 2002/2006/2010 = 88; Qld 2001-2015 = 89, 2017 = 93; SA 2002-2018 = 47; WA 2001 = 57. No R or script code reads this folder today (grep of `R/` and `scripts/` found nothing).
   Accuracy check: I summed AE's first-preference votes per seat and compared with our official files. Vic 2010: 88 of 88 seats within 0.2%. SA 2018: 47 of 47. Qld 2017: 92 of 93 (Capalaba differs). NSW 2015: 92 of 93 (Prospect differs). Vic 2014: 85 of 88 (Ferntree Gully, Clarinda, Altona differ). So AE's copy is good but not exact; where the commission publishes, use the commission file and use AE only to cross-check or fill.
2. **No preference distributions (transfer rounds) exist in AE's files.** The harnesses need the previous election's transfers to build flows, so this is the real gap, not first preferences. How each harness gets flows (read from the scripts):
   - NSW harness: only NSW's own previous-election transfers from `nswec-nsw-transfers.csv`, asserted. It states pooling Queensland or WA made NSW 0.194 log score worse because NSW is optional preferential.
   - Vic harness: `vec-<from>-vic-transfers.csv`, hard-coded to the previous election's file, then `pool_configured_flows`.
   - Qld harness: `PAIR$flow_file` per pair. The 2020 pair uses `aec-fed-transfers.csv` (federal 2019) because Qld 2017 had no distribution file. The 2024 pair uses Qld's own 2020 transfers.
   - SA harness: always `aec-fed-transfers.csv` filtered to one federal election (`flow_from`), so SA pairs need no state transfers.
   - Fed harness: prior federal elections' transfers.
3. **Hard blockers in code, not data** (to fix after the production rebuild finishes; none touched here):
   - NSW harness calls `load_seats(TO, "nsw")` with no fallback (line 387), reads `seats` again for `seat_swing_spread` (line 903) and `load_seats(PAIR$next_seats)` for the winner cross-check. The anchor only ships seat files for 2019 and later (`analysis/seats/`: 2019fed, 2019nsw, 2022fed/sa/vic, 2023nsw, 2024qld, 2025fed/wa, 2026sa/vic, 2027nsw, 2028fed). Every NSW pair before 2019 needs a Queensland-style fallback.
   - SA harness: `seat_swing_spread(load_seats(TO, "sa"))` at line 1037 has no fallback. Same fix.
   - Qld harness already has the fallback (lines 875-885, uses the 2024 file) and the fed harness wraps `load_seats` in `tryCatch`. Vic wraps it at line 731.
   - Each harness has a hard-coded pair list (`NSW_PAIRS`, `QLD_PAIRS`, `SA_PAIRS`, vic `PAIRS`, fed `PAIRS`) and per-pair date tables (`VIC_DATE`, `FED_DATE`, NSW `c("2019"=...)`). `all_election_pairs()` and `election_dates()` also need new entries. `election_dates()` has no entry before fed2004, nsw2015, qld2017, sa2018, vic2010. The dates are all in the anchor's `Data/election-cycles.csv`.
   - `STATE_REDISTRIBUTIONS` (`R/state_notional.R`) lists no pre-2014 state redistribution. Each redistributed pair also needs a notional file from `scripts/build_state_notionals.py`, which needs polling-place results for BOTH elections in `output/booths/` (see the booth table in `docs/DATA-REGISTRY.md`).
   - Candidate names: `scripts/build_candidacies.R` has a dedicated block per election; each new election needs one (AE csv or the commission file carries names).
4. **Beyond the base harness score, the shipped model's extra-features layer is thinner for old elections.** `published_flags.R` ships `AUSPOL_XGB_PRIMARY=1` with council history, leaders, retirements and census features. On disk: census SED/CED only for 2016 and 2021 (`external/reference/census/`); leaders.csv covers fed2007+ and, in the part I counted (first 12 election groups), NSW/Qld only from 2019/2020 (Vic, SA, WA not checked); retirements.csv starts fed2004, nsw2015, qld2017, sa2018, vic2010. The as-at xgb models need at least 4 earlier pairs (`AUSPOL_ASAT_MIN_PAIRS`), so a new early pair has none and falls back to the base model. Decision for Pete: score old pairs on the base model only (cheap, honest) or backfill census 2006/2011 and leaders (extra work, unchecked: ABS DataPacks URL not tried).
5. **AE Forecasts published nothing before 2022**, so none of these older pairs has a rival benchmark.

## Recommended order (2010+ first)

Every step uses the commission file as the primary and the AE csv as a cross-check. Each step adds a pair to all six harnesses where it applies (CLAUDE.md: a fix to one harness is a fix to all).

1. **vic2010 (from vic2006).** Smallest gap: the VEC blob already has the 2006 distribution pages and district totals can be summed from booth data on disk. No redistribution, no seat-file problem. Do this first to prove the "add a pair" mechanics end to end.
2. **qld2017, qld2015, qld2012 (ECQ zips).** One schema, three downloads already confirmed live. Decide the flow source first (federal flows are compulsory preferential; Qld was optional preferential until 2017) and run the pairs with the same code path qld2020 uses. Redistribution before qld2017 needs a notional from qld2015 booth data (same XML).
3. **sa2018, sa2014, sa2010 (ECSA HTML).** Add a seat-file fallback to the SA harness, add the sa2018 winners row, scrape 47 district pages per election. Flows from the federal files already on disk.
4. **nsw2015 (from nsw2011).** NSWEC 2011 pages are live including preference distributions, so this pair is feasible with its own transfers. Needs the NSW seat-file fallback and a new parser for the 2011 page layout.
5. **fed2004 (from fed2001).** One parse of the AEC 2001 statistics zip gives first prefs, candidates and a full distribution. Do before nsw2011.
6. **nsw2011 (from nsw2007)** only if Pete accepts federal flows for NSW or the 2007 transfers turn up. No online source found.
7. **2000-2009 elections** (fed2001, nsw2003/2007, vic2002/2006, qld2001-2009, sa2002/2006): AE csv gives first prefs and winners for all of them on disk today, so the base score is feasible without any download. The blockers are state transfers (not found), polling-place data for notionals, and the thinner extras layer. Treat as a separate wave after 2010+.
